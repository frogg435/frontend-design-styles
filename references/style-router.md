# 风格选型路由

用户没指定风格时，按下表推荐。**给 1 个主推 + 1 个备选，并说明理由**，让用户确认后再动手。

## 决策树

```
产品面向哪个平台？
├─ 小米 / 澎湃 OS 生态，或 Android 国内机型
│   → MIUIX / HyperOS
│   （如果用户说"国产安卓风""小米风""像 MIUI"也走这条）
│
├─ iOS / iPadOS / macOS，或"要像原生 App 一样精致"
│   → Apple HIG
│
├─ 跨平台 Android 应用、面向全球的 C 端产品、需要动态取色
│   → Material Design 3
│
├─ Windows 桌面应用、企业办公 / B 端后台 / 数据密集工具
│   → Fluent 2
│
└─ 不确定 / 多平台
    ├─ 移动优先、消费级、要"高级感"  → Apple HIG
    ├─ 移动优先、要个性和色彩表达    → Material Design 3
    └─ 桌面优先、信息密度高          → Fluent 2
```

## 按维度打分

| 维度 | MIUIX | Apple HIG | Material 3 | Fluent 2 |
|---|---|---|---|---|
| 信息密度 | 低–中 | 低（移动）/ 中（macOS） | 中 | **高** |
| 视觉华丽度 | 中（圆润通透） | **高**（材质/景深） | 中–高（色彩表达） | 低–中（克制专业） |
| 实现复杂度 | 低 | **高**（材质、连续圆角、安全区） | 中 | 中–高（材质降级、密度模式） |
| 暗色适配难度 | 低 | 中 | **低**（色调映射天然支持） | 中 |
| 设计令牌成熟度 | 中（开源库默认值） | 中（官方给语义色与字阶） | **高**（完整三层令牌体系） | **高**（完整三层令牌体系） |
| 无障碍基线 | 需自行补 | 强（Dynamic Type） | 强（对比度规则明确） | **强**（对比度 + 高对比模式 + 键盘） |
| 动态主题 | 支持（Monet 动态色） | 无 | **原生支持** | 支持（品牌色阶替换） |
| 桌面端适配 | 弱（为触屏设计） | 中 | 中 | **强（原生桌面）** |
| 移动端适配 | **强** | **强** | **强** | 弱（需放大控件） |
| 中文生态适配 | **强（MiSans 原生中文）** | 中（需配苹方） | 中（需配 Noto Sans SC） | 中（需配雅黑） |

## 场景速查

| 场景 | 推荐 | 理由 |
|---|---|---|
| 小米生态 App / 澎湃 OS 应用 | MIUIX | 原生一致性最高，MiSans 中文最优 |
| 国内安卓工具类 App | MIUIX 或 Material 3 | 前者更贴近国内用户审美，后者生态工具更全 |
| 高端消费级 iOS App | Apple HIG | 用户对原生质感有肌肉记忆 |
| 出海 C 端 App（Android） | Material 3 | 全球化认知成本最低，动态取色加分 |
| 企业后台 / 数据看板（桌面） | Fluent 2 | 高密度、键盘操作、专业感 |
| Windows 桌面客户端 | Fluent 2 | Mica/Acrylic 融入系统 |
| 跨平台 SaaS 官网 / 营销页 | Material 3 | 组件全、色彩表达强、落地页好做 |
| 电商 / 生活服务 App（移动） | MIUIX 或 Apple HIG | 按目标机型选 |
| 开发者工具 / 代码编辑器界面 | Fluent 2 | 紧凑密度 + 等宽字体 + 键盘优先 |
| 金融 / 医疗等高信任场景 | Apple HIG 或 Fluent 2 | 克制、清晰、无障碍强 |

## 混搭禁区（不要做）

四套体系的差异在于**整套视觉语法**，不是配色。以下混搭会立刻露馅：

| 禁止的组合 | 为什么崩 |
|---|---|
| Material 的 pill 按钮 + Fluent 的小圆角卡片 | 圆角语言冲突，一个"团"一个"方" |
| iOS 的模糊材质 + Material 的色调叠加 | 两套层级表达方式打架，层级读不出来 |
| HyperOS 的大圆角 + iOS 的 `#007AFF` | 蓝色色相不对（`#3482FF` vs `#007AFF`），一眼假 |
| Fluent 的 32px 控件 + iOS 的 44pt 点击目标 | 密度和可点性矛盾，实际用起来别扭 |
| Material 的 FAB + 其他任何体系的导航 | FAB 是 Material 独有签名 |
| 一套体系的字阶 + 另一套体系的行高 | 字阶和行高是配套设计的 |

**允许的借鉴**：无障碍做法（谁都能用 WCAG）、动效曲线（曲线可以跨体系借用但不改时长量级）、栅格系统（8pt 是通用共识）。

## 选型后必做

1. 明确说明选了哪套、为什么，以及是否为多平台做了取舍。
2. 如果用户的产品同时覆盖多端（比如 iOS + Android），明确告知：**要么统一用一套体系做成品牌化设计，要么按平台各自原生**——不要做"四不像的中间态"。
3. 询问是否需要同时产出暗色模式。四套体系都有官方暗色值，成本很低，默认建议做。
